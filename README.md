# FunGames

FunGames یک پروژه چندنفره با C++ و Qt است که شامل یک کلاینت گرافیکی و یک سرور TCP برای اجرای بازی های رومیزی آنلاین است. کاربرها می توانند ثبت نام/ورود کنند، پروفایل خود را مدیریت کنند، مسابقه بسازند یا به مسابقه موجود وصل شوند و تاریخچه بازی ها را ببینند.

## امکانات

- رابط کاربری گرافیکی با Qt Widgets
- ثبت نام و ورود کاربران با ذخیره محلی اطلاعات
- هش کردن رمز عبور با SHA-256
- اعتبارسنجی ایمیل، شماره تلفن و فیلدهای ثبت نام
- ارسال کد تایید ایمیل از طریق SMTP
- مدیریت پروفایل کاربر و امکان تغییر اطلاعات
- اتصال کلاینت ها به سرور TCP روی پورت `12345`
- ساخت و مشاهده مسابقه در لابی
- پشتیبانی از دو بازی:
  - Othello / Reversi
  - Connect Four
- انتخاب رنگ میزبان و محدودیت زمانی بازی
- ارسال پیام های بازی با JSON روی TCP
- ثبت تاریخچه مسابقه ها در SQLite
- Dockerfile برای ساخت و اجرای سرور

## پیش نیازها

برای build و اجرای پروژه به موارد زیر نیاز دارید:

- C++17
- Qt 5 یا نسخه سازگار با qmake
- ماژول های Qt:
  - `core`
  - `gui`
  - `widgets`
  - `network`
  - `sql`
- درایور SQLite برای Qt، معمولا بسته `libqt5sql5-sqlite`
- ابزارهای build مثل `make` و `g++`

نمونه نصب روی Ubuntu/Debian:

```bash
sudo apt update
sudo apt install build-essential qtbase5-dev qtchooser qt5-qmake qtbase5-dev-tools libqt5sql5-sqlite
```

## راه اندازی سریع

### 1. ساخت سرور

```bash
cd FunServer
qmake FunServer.pro
make
```

اجرای سرور:

```bash
./FunServer
```

سرور به صورت پیش فرض روی پورت `12345` گوش می دهد.

### 2. ساخت کلاینت

در یک ترمینال دیگر:

```bash
cd FunGames
qmake Project.pro
make
```

اجرای کلاینت:

```bash
./Project
```

اگر نام فایل خروجی در محیط شما متفاوت بود، فایل اجرایی ساخته شده در همان پوشه build را اجرا کنید.

### 3. اتصال کلاینت ها

برای بازی چندنفره، دو نمونه از کلاینت را اجرا کنید و هر دو را به IP سرور و پورت `12345` وصل کنید. اگر سرور روی همان سیستم اجرا شده است، معمولا می توانید از یکی از این آدرس ها استفاده کنید:

```text
127.0.0.1
localhost
```

برای بازی روی شبکه محلی، IP دستگاهی که سرور روی آن اجرا شده را وارد کنید.

## اجرای سرور با Docker

داخل پوشه `FunServer`:

```bash
docker build -t fungames-server .
docker run --rm -p 12345:12345 fungames-server
```

بعد از اجرای کانتینر، کلاینت ها باید به IP میزبان Docker و پورت `12345` وصل شوند.

## نحوه استفاده

1. سرور را اجرا کنید.
2. کلاینت را اجرا کنید.
3. در صفحه Login/Signup حساب بسازید یا وارد شوید.
4. در صفحه اصلی، IP سرور را وارد کنید و به سرور متصل شوید.
5. یکی از نقش ها را انتخاب کنید:
   - `Host`: ساخت مسابقه جدید
   - `Guest`: مشاهده و پیوستن به مسابقه های ساخته شده
6. میزبان نوع بازی، رنگ و زمان را انتخاب می کند و مسابقه را می سازد.
7. مهمان از لیست مسابقه های فعال یکی را انتخاب می کند و وارد بازی می شود.
8. بعد از پایان بازی، نتیجه در تاریخچه ذخیره می شود.

## پایگاه داده

این پروژه از SQLite استفاده می کند.

### دیتابیس کلاینت

اطلاعات کاربران در سمت کلاینت و در مسیر AppData سیستم ذخیره می شود. نام فایل دیتابیس:

```text
users.db
```

جدول اصلی:

```sql
users(id, username, name, email, phone, password)
```

رمز عبور قبل از ذخیره با SHA-256 هش می شود.

### دیتابیس سرور

سرور فایل زیر را در مسیر اجرای خودش می سازد:

```text
fungames.db
```

جدول تاریخچه مسابقات:

```sql
match_history(
  id,
  game_type,
  player_black,
  player_white,
  winner_username,
  black_score,
  white_score,
  date
)
```

## پروتکل ارتباطی

ارتباط کلاینت و سرور با `QTcpSocket` و پیام های JSON انجام می شود. هر پیام به صورت JSON فشرده ارسال شده و با کاراکتر newline پایان می یابد.

نمونه پیام معرفی کاربر:

```json
{"type":"login","username":"mahdi"}
```

نمونه پیام ساخت مسابقه:

```json
{
  "type": "create_match",
  "game": "othello",
  "hostColor": "black",
  "timeLimit": 60
}
```

نمونه پیام حرکت در Connect Four:

```json
{
  "type": "connectFour",
  "msgType": "move",
  "column": 3,
  "color": "black"
}
```

نمونه پیام حرکت در Othello:

```json
{
  "type": "othello",
  "msgType": "move",
  "row": 2,
  "col": 4
}
```

## نکات مهم

- پورت سرور در کد `12345` است. اگر این پورت اشغال بود، مقدار آن را در سرور و کلاینت هماهنگ تغییر دهید.
- سرور فعلی برای اتصال و هماهنگی دو کلاینت طراحی شده است.
- برای استفاده از قابلیت ارسال ایمیل، اتصال اینترنت و تنظیمات صحیح SMTP لازم است.
- اطلاعات SMTP نباید به صورت ثابت داخل کد نگهداری شود. بهتر است برای نسخه عملیاتی از متغیر محیطی یا فایل تنظیمات خارج از مخزن استفاده شود.
- اگر ایمیل تایید ارسال نمی شود، تنظیمات حساب Gmail، App Password، فایروال و دسترسی شبکه را بررسی کنید.
- فایل های دیتابیس runtime هستند و بهتر است داخل git ثبت نشوند.
